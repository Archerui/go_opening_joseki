# 围棋开局定式大全

以单个 19 路棋盘为主体的离线定式浏览器。没有构建步骤，没有实时 AI，也不调用远程分析服务。

## 操作

- **左键候选点**：始终按黑白交替落子，只显示当前行棋方的候选；点其他空位可正常落子。未收录位置不被判为坏棋。
- **悬停候选点或右侧列表**：显示半透明的后续结果图，已知名定式显示名称。浮窗不接收鼠标，离开候选立即关闭，移到另一候选立即切换。点击侧栏“预览”可固定窗口，操作来源分支或整段落子。预览中的数字是后续手顺；棋盘候选按实际落点连续编号，不是胜率。同点不同条件共用编号，在侧栏相邻列出，配子与后续保持独立；脱先没有棋盘坐标，单独以箭头显示，不占编号。
- **实际脱先**：在棋盘远处真正下一手，轮次正常交替；角上棋形未变时保留定式进度，并继续推荐当前方的局部应法，例如双飞燕。没有手动切换黑白的控件。
- **右键候选点或固定的预览浮窗**：执行浮窗中实际展示的整段变化。每手都进入历史，可逐手回滚。
- **棋盘内滚轮**：向上回退，向下前进；按滚动距离连续走多手，鼠标滚轮和触控板的小幅输入都会累计。反向滚动立即响应，停顿或使用其他导航后清除残量。前进优先重放历史；没有历史时仅沿唯一的来源优先建议或唯一无条件续着前进；缺少明确依据的分叉等待选择。自动前进不替任何一方脱先；请在棋盘上选实际落点，已选历史照常重放。边界处不滚动页面。
- **← / →、Home / End、时间滑条**：浏览落子历史。回退后另下一个点会替换原后续分支。
- **触屏**：使用候选旁的“预览”和浮窗中的“落下这段变化”，用棋盘下方箭头回退。
- **方向选择**：旋转及镜像共八个方向。手数显示、原谱错着显示可以切换。
- **定式库**：按来源浏览完整树，搜索中文精选/名型，或直接进入错误发生之前的局面。
- **局面链接 / SGF**：复制包含历史的局面链接，或下载当前手数以前的棋谱。SGF 保留配子、脱先、指定行棋方、评注及来源。

名称按实际手顺识别，来源名不充当定式名；不明名称不显示。已核对 532 个局面的来源建议及局部说明，覆盖六类开局的前三手全部来源分支和部分主要后续。全库 2,330 处分叉中 333 处匹配这些核对数据；其余不冒充已经确定最佳次序。预览在定式终点或缺少唯一优先依据的分叉处停止。详见 [名称与次序说明](data/NAMING-AND-ORDER.md)。

绿色表示来源采用的应法；红色仅表示原谱明确标注的错误；黄色表示条件变化、疑问、嵌手或引擎规避；灰色为未评级。深绿色突出已核实的教学首选参考，较浅绿色保留其他应法和旧库支线；没有伪造数值评分。不同来源对同点意见冲突时显示“来源标注有分歧”，可在预览中选择来源。

## 本地运行

```sh
cd template
python3 server.py 8000
```

打开 <http://localhost:8000/>。也可以直接打开 `index.html`；静态 JS 数据使用普通 script 标签载入，不依赖 fetch。复制链接的能力受浏览器剪贴板权限影响，失败时会把局面写入地址栏以便手动复制。

现有服务器的 `go-joseki.service` 使用 `server.py` 服务本目录，继续监听 **9310**，监听地址和防火墙设置不变。所有资源返回 `Cache-Control: no-cache`，普通刷新会验证文件是否更新，未修改的文件仍可使用 304 缓存。脚本、样式和字体的资源地址也已加入版本参数，绕过此前没有更新校验的旧缓存。可用 `systemctl --user status go-joseki.service` 查看状态。

## 棋谱处理

- 按树结构保存正常和错误分支，不将变化展平成互相无关的演示图。
- 元数据节点不占手数；`AB/AW/AE` 配子会应用到预览与执行局面，并提示额外配置。
- 支持提子、自杀禁止、简单打劫。原谱同色连续落子表示省略对方在别处的脱先；`PL` 指定行棋方得到保留。
- 同点同局面的来源合并显示；行棋方、打劫历史或配子状态不同的分支保持独立。
- 预览沿所选来源的一条分支继续，不自动补造后续；到达仅含错着或无法合法继续的边界会明确提示。
- 征子条件只保留并提示，不自动判断全盘征子。未收录落点可以自由研究，但不会自动产生评价或惩罚。

## 维护和验证

更新原始数据及清单后可以重建：

```sh
python3 scripts/build-joseki.py
python3 scripts/verify-joseki.py
node --test tests/engine.test.cjs tests/knowledge.test.cjs tests/review.test.cjs tests/review-library.test.cjs tests/context.test.cjs
node scripts/audit-order.cjs
```

构建默认离线，先校验原始文件哈希；`--fetch` 从清单中的固定提交恢复数据，不自动追踪最新分支。全树验证检查父子关系、范围、占位冲突、提子、自杀和同父同点重复。

浏览器回归使用 Playwright Core 和本机 Chromium，不是网站的运行依赖：

```sh
npm install --prefix /tmp/fangcun-qa playwright-core@1.51.1 --no-save --no-package-lock
NODE_PATH=/tmp/fangcun-qa/node_modules \
CHROME_PATH=/path/to/chromium \
JOSEKI_URL=http://127.0.0.1:9310/ \
node --test tests/browser.test.cjs tests/candidate-turns.test.cjs tests/tenuki.test.cjs tests/wheel.test.cjs tests/numbering.test.cjs tests/named-library.test.cjs tests/mi-family.test.cjs tests/cache-refresh.test.cjs tests/hover-preview.test.cjs
```

浏览器测试覆盖错着预览与执行一致性、滚轮历史、八向坐标、自由落子、条件提示、指定行棋方、窄屏浮窗、局面链接恢复。源码无需 npm 安装即可运行。

主要文件：`app.js`（树浏览与交互）、`engine.js`（不可变棋盘规则）、`joseki-knowledge.js`（名称）、`joseki-review.js`（核实次序与终点）、`data/joseki-db.js`（生成的批量库）、`curated-joseki.js` 及三个原有精选模块、`styles.css`、`index.html`。中文字体为按本站文本重新精简的 Noto Sans SC / Noto Serif SC；原 SIL Open Font License 保留在 `assets/fonts/`。


## 行棋方与同点分支核对

`node scripts/audit-candidate-turns.cjs` 全库回放并检查同点的黑白候选。原始来源的 17 个局面有 21 处同点两色记录；按完整状态合并来源后为 19 个局面、24 处。截图局面为 `B R16 → W P17`（Pachi 节点 1507），Q14 与 Q15 均有黑白两种后续。

交互落子始终黑白交替，只推荐当前方。原谱中的连续同色变化不再靠切换颜色执行：先在棋盘远处真正下一手，局部未变时继续匹配其后续。5 条配子后应白先的精选条目按首步颜色恢复正确初始行棋方。初始配子局面可以指定先手；一旦已有落子，即使原谱途中有 `PL`，也由上一手的另一方行棋，装载后的当前行棋方也按最后一手计算。源谱历史仍展示其记录的手顺，省略的远处着不伪造。

`joseki-context.js` 独立保存已知局部棋形及来源进度。实际棋盘负责合法性、劫禁、提子和手数；远处实着只推进实际回合。源谱明确记了 pass 时，远处实着满足这一次局部脱先，不在真实历史中额外添加 pass。省略 pass 的连续同色原谱也能接续。分享链接、回退与重做重建同一局部进度，预览和执行保留实际远处棋子。

局部保护范围采用已有棋子的包围盒加 3 格，及直接候选/配子周围 2 格；落在保护范围内的未知着、改变局部棋子的提子均使旧匹配失效。它只维持仍符合棋形的来源记录，不评估全盘配置或征子。空棋盘上任意下子不会凭空匹配一个角部定式。
